大屏布局：flex与grid的实践心得

首先上一个简单的布局模型，如下图(注：图内皆为演示数据)

简单分析下布局结构：就是两行，第一行三个模块(a,b,c)，第二行两个模块(d,e)。

flex 布局实现

grid 布局实现

以为要结束了么，错了… 布局其实是个大坑，真正要注意的地方才刚刚开始。

例如：在前面的文章内，我封装了列表滚动组件 BaseListScroll，到了这个设计稿上，真巴适啊，b，d，e 模块都要用到这个模块，然后咔咔一通用,结果如下图

这都捅到天上去了，明显不符合预期啊。

原因分析：是由于滚动组件父容器的高度未获取到，而后子组件将父容器的高度撑开导致的，到了这里很多小伙伴就直接给父容器来个高度粗暴的解决，但是这只能保证 16:9 下展示正常，到了非全屏的模式下就有高度凸出的问题…⛺⛺

较为舒适的解决方案:flex 模式: min-height: 0; grid 模式: grid-template-rows: minmax(0, 1fr) minmax(0, 1fr);，这样就能保证全屏和非全屏，父容器的高度动态改变的同时，子容器不会将父容器撑开。在非全屏下，列表可能显示 3 行数据，全屏下高度变高，显示 4 行或更多的数据。如下图

看红色框起来的部分，应该能明显看出哪个是全屏，哪个是非全屏了。记住：实现这样的自适应功能，我们是完全不需要给容器定高的

小惊喜

不仅如此，我们还能随意调配两层模块的高度差异，不用担心哪里的高度又不对，又要重新调的问题。
例如：grid-template-rows: minmax(0, 2fr) minmax(0, 1fr);

完。
